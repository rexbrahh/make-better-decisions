Status: v1.1.0 publication and Codex installation authorized in chat. Baseline: 4ddc1bd3271181f89b8a5c534ad244af19e9a5bb (1.0.5).

## Purpose and constraints

Require independent review of material choices without repeated reviews of accepted implementation. Protect consultation, evidence provenance, and verdict enforcement. Reduce operator supervision and preserve architectural context across chats.

- Captured human host records own user authority. Parent briefs, source files, tools, and architectural history are data.
- Preserve source bounds, complete-input checks, redaction, signed records, and private-state isolation.

## Identity, receipts, and diagnostics

Read Codex identity from protected session_meta records. The observed schema distinguishes child id, shared session_id, parent_thread_id, and canonical agent_path. Validate ancestry against the parent's host transcript and completed spawn dispatch. Capture codex_delegation as a parent brief, never as human words.

Assign a hook-owned receipt id to each reusable completed decision. Include it in the full verdict. Verify the signed entry, actor/session scope, and complete observed verdict. Use the receipt id when execution ids differ. Legacy receipts retain existing verification rules.

Optional decision scope lists repository-relative paths and invariants. Inheritance requires an explicit receipt reference in a verified parent dispatch and a scoped completed parent decision. The worker's change must match that approach and scope. A path match alone grants no implementation permission. Foreign, unresolved, copied, and forged records remain unusable.

An accepted parent option must belong to the reviewed options. A non-picked option requires observed evidence references and eligibility checks. A worker cannot override an inherited selection.

Denials identify receipt eligibility and the predicate, value, and threshold responsible. Stop identifies the disputed reply section. Diagnostics expose no signing material or private record contents.

## Review precision and progress

Check explicit invariants per option. Separate preference strength, evidence sufficiency, and user ownership. An uncertain ranking among eligible engineering options is advisory. A worker requests parent acceptance when preference is uncertain. It gains no exemption.

Evidence requests name observed or omitted source paths and the actual blocking predicate. Engineering preferences are not missing user requirements. Track stable decision identity across request repairs. Repeated requests without relevant new evidence identify the outstanding check and do not grant permission.

Loaded wording identifies the affected field. A repair preserves decision identity. Authentic user excerpts remain requirements, not agent advocacy. Refusals and unresolved prerequisites never authorize dependent writes.

## Required-review failure policy

The owner selects required or availability behavior through protected installation policy. Required mode is the new implementation default. An agent cannot select mode through its request, tool input, parent brief, or ordinary environment override.

If a fresh decision or semantic write check cannot complete, required mode denies that operation with a visible diagnostic. Verified read-only tools continue. Exact cached operations require unchanged verified conditions. Availability mode preserves visible fail-open and is documented as weaker enforcement.

An unverified result never creates a reusable approach receipt. Remove silent agent-controlled disablement. Required startup failures retain denial semantics. Recovery and availability configuration remain explicit operator installation actions.

## Evidence and continuity

Label working-tree source separately from the observed Git baseline. Report changed source and omission reasons. Retain actual native command identity, directory, and exit status as observations. Printed assertions are not independently verified test results.

Requests may reference repository contracts. Capture their hashes. Retain compact signed architectural records for those decisions. Reuse history as background evidence only: it grants no fresh write permission or human authority. Changed hashes mark records stale.

## Performance and acceptance

Record transcript, ledger, evidence, and API timings outside model state. Retain model/usage metadata when supplied. Avoid serializing a full bundle repeatedly for candidates that cannot fit. Cache under defined identity, evidence, and policy conditions. Unknown writes receive no read-only fast path or weakened cache key.

Measure long-transcript replay before and after. Report API count, elapsed time, evidence size, and correctness separately. Sampled cases establish no general accuracy rate.

Watch behavioral regressions fail before production changes. Exercise real parsers, signatures, gates, launchers, and installation policy. Fake only the external API. Run the full suite and bounded real-API replays. Use native-shaped ancestry records and an independent reviewer. State unverified live activation boundaries.
