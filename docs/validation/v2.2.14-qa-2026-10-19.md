# v2.2.14 answer capture and history validation — 2026-10-19

This release corrects two confirmed Codex answer-capture defects.

| Defect | Repair | Evidence |
| --- | --- | --- |
| A completed native asynchronous question had a 524-byte title and an exact 512-byte echoed prefix. Full-title matching rejected its answer. | Permit that bounded, valid UTF-8 prefix for the matched asynchronous call. | The exact extracted native record fails before the repair and passes afterward. An older exact-title native control also passes. |
| A legacy signed snapshot already contained a later human instruction but omitted the historical answer. Recovering the answer appended it after that instruction. | Require the complete signed word sequence, then insert accepted replies in current native order. | A controlled signed-snapshot regression fails with `original, later, reply` before the repair and passes with `original, reply, later` afterward. |

Only decoded answers supply user authority. The repeated question remains agent text.
The parser retains completion, tool, call-ID, item-index and human-origin checks.
Exact title matches remain compatible with other question tools.
The truncation fallback requires exactly 512 bytes, a longer title, a matching prefix and valid UTF-8.

The upgrade check preserves signed word order and multiplicity.
It rejects incomplete histories before consuming a matching prompt or marking the reply seen.
Complete context can then recover the answer once.
Current protected native order supplies the position of a previously unseen record.
The earlier snapshot cannot independently establish that missing record's former position.
Ordinary prompt matching and Claude answer handling retain their existing behavior.
