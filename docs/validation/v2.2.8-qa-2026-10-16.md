## Selected diagnostic repair

The owner selected the exact metrics design before implementation.
Future unreachable Jev calls can retain their failure phase in existing API metrics.

| Confirmed issue | Repair | Evidence |
| --- | --- | --- |
| Request and response-body failures produce the same public error and existing metrics. | Add optional `JevError.Phase` metadata. Record only `request` and `response_body` as `api_calls[].error_phase`. | Injected Go and frozen Python failures reproduce the missing distinction. Both client and hook regressions fail before the repair. |

`request` identifies a failure returned by `http.Client.Do`, including the request and header exchange.
`response_body` identifies a failure while reading a successful response body.
These labels identify an exchange phase. They do not identify a network or backend cause.
The client sets a label only for `unreachable`. The hook omits empty and unknown labels.

The repair adds no raw transport error, endpoint, key, request body or response body to metrics.
Public error text, Python error identity, model state, questions, receipts and review policy retain their existing behavior.
Deadlines, retries and body cleanup also retain their existing behavior.
Jev remains the normal default. Snap remains opt-in.
