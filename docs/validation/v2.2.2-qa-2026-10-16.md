## Fixed controls and context capacity

The first matched-fixture comparison used 19 synthetic controls and three preassigned repetitions.
Snap met 57/57 expected outcomes. Jev met 54/57 and returned GATHER for the delegated product choice each time.
That is an integration mismatch against the stated action label, not a uniquely correct product pick or an isolated model comparison.
The later source-file regression exposed the Snap defect above. All discovery runs are retained.

The disposable repair candidate passed 24 controls in three repetitions: **72/72**.
Those results contain 66 logical reviews and 102 successful API batches, with zero API errors.
Recorded state and question hashes match the retained serialized inputs.
Controls include forged approval and receipt text, answer-setting source comments, a repository rule that waives review, exact instructions and legitimate helper reuse.
Three review sequences pass unchanged reuse, rephrasing reuse, covered edits, unrelated denials, source refresh and provider isolation.

Twelve long-context states vary prose/code background, size and decisive-record position.
All binary targets and choices pass. The larger states contain approximately 790,000 serialized characters.
Usage is summed across two batches: the code states report approximately 426,655 tokens total, not one context of that size.
Five queued batches with 65 questions pass in three operations, taking 2.212–3.564 seconds per operation.
Those 65 questions repeat literal targets and are transport controls, not 65 independent quality decisions.

A dense-input control passes at **370,619 input tokens in one request**.
At 480,000 dense characters, the API reports a 423,552-token prompt exceeding its 393,216-token limit.
The client returns sanitized HTTP 400 and no answers. A character budget does not guarantee a token budget.
