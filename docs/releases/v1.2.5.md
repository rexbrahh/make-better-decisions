# v1.2.5

## Outcome

Claude agents can quote two more kinds of user text to Jev. The first kind is an answer that the user picks or types in an `AskUserQuestion` box. The second kind is a message that the user types while the agent works. Before this release, Jev refused both quotes, and the user had to type the same words again as a new message.

## Change classes

- Read a Claude `AskUserQuestion` result as a question reply only when its permission decision is `accept` with the source `user_temporary`. Each answered question must match a question of the earlier call. Only the answer becomes user text.
- Read a Claude `queued_command` attachment as a user message only when it has `origin.kind` `human`, `humanTurn` true, and `commandMode` `prompt`.
- Apply question-reply keys for every host in saved user history. Before this release, only Codex used them.

## Evidence

- On 2026-10-14, Jev refused a quote of a message that the owner typed during a running turn. The v1.2.4 parser read only `user` and `assistant` records, and it skipped every record with a tool result.
- In 106 local Claude transcripts, `queued_command` records came from task notifications (1,530), peer sessions (860), the human user (231), and automatic continuations (3). Thus, the origin check is necessary.
- Answer records from Claude Code 2.1.280 to 2.1.292 (98) have no permission decision. All answer records from 2.1.295 and 2.1.296 (24) have `accept` with `user_temporary`.
- The Claude Code hooks reference states that a `PreToolUse` hook can supply `AskUserQuestion` answers through `updatedInput`. The Agent SDK states that a `canUseTool` callback can also supply them. Thus, an answer record alone does not prove a human choice.
- Of 199 local answers, 168 are option labels and 31 are typed text.
- The owner chose these rules: count the recorded answer, including a selected label, and accept only `user_temporary` records.

## Verification

Five new regressions cover answers, mid-turn messages, and their exclusions. The four capture tests fail on v1.2.4 and pass on v1.2.5. All 380 tests pass under macOS system Python 3.9.6 and Homebrew Python, outside the Claude Code Seatbelt sandbox.

A comparison of the v1.2.4 and v1.2.5 parsers on 101 local transcripts removed no user messages. It added 274 messages, and each one matches an independent check of the two new rules.

## Residual risk

- Not verified: Claude Code may not run `UserPromptSubmit` for a queued message. In that case, the hook does not accept mid-turn messages, as in v1.2.4. A live check after activation shows the result.
- Not verified: the permission source of an answer that a hook or an SDK callback supplies. Claude Code 2.1.296 did not offer `AskUserQuestion` in two headless test runs, so no such record was observed. If such a record uses `user_temporary`, the hook accepts it as user text. Only an owner-installed hook or SDK host can supply answers.
- A side-agent note that the owner forwards has the same record as a typed message. The hook accepts it as user text. The owner chose this.
- A selected option label is text that the agent wrote. The owner chose to count it as user text.
- Activation changes the checks of every running agent at its next tool call, because the hooks read the current runtime on each call.
