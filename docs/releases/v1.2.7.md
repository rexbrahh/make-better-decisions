# v1.2.7

## Outcome

The private-state guard checks a shell word with braces in linear time. In v1.2.6, a 10 KB command could stop the guard for longer than the 15 s hook timeout.

## Change classes

- Replace the brace pattern `\{([^{}]*,[^{}]*)\}` with `\{([^{},]*(?:,[^{},]*)+)\}`. Commas split the parts, so a failed match backtracks linearly. The guard decisions do not change.

## Evidence

- On 2026-10-14, an automated security review of the v1.2.6 commit reported possible algorithmic denial of service in the guard.
- The v1.2.6 pattern backtracks quadratically on an unclosed brace that contains many commas. The guard runs the pattern again for each of the 64 brace expansions.
- In the live v1.2.6 bundle, `echo` followed by six `{a,b}` groups, one `{`, and 10,000 commas took 25.6 s. The `PreToolUse` hook timeout is 15 s.
- The new pattern took 0.3 ms on 10 KB and 30 ms on 1 MB. On 200,000 random words, it gave the same match span and group as the old pattern.
- Jev picked this fix and no length limit (ADVISORY, `review_d30bbc17`). The owner approved v1.2.7.
- Brace or `**` nesting deeper than the Python recursion limit raises `RecursionError`. The hook turns each exception into a denial. Thus, this release does not change that path.

## Verification

A new regression checks six brace groups and an unclosed brace with 5,000 commas. It took 6.2 s on v1.2.6 and failed. It passes on v1.2.7 within its 1 s limit. All 386 tests pass under macOS system Python 3.9.6 and Homebrew Python 3.15, outside the Claude Code Seatbelt sandbox.

A scan compared the live v1.2.6 bundle and v1.2.7 on 93,481 tool calls from local Claude and Codex transcripts. No guard decision changed.

## Residual risk

- The behaviour of Claude Code and Codex when a hook passes its timeout is not verified. If a host lets the call continue, another slow path in a hook can bypass the guard. The host sandbox still denies the state directory.
- Activation changes the checks of every running agent at its next tool call.
