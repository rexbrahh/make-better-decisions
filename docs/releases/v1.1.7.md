# v1.1.7

## Outcome

Decision hooks now use less memory when they load long chats. A 497.2 MiB native transcript peaked at 323.2 MiB RSS after the correction, compared with 1,159.6 MiB before it: approximately 72% lower. All 14,923 tool calls and the full parsed-result fingerprint matched. Post-activation hook samples used 36.5 to 167.5 MiB RSS.

## Change classes

- Stream transcript records instead of retaining every decoded raw record. Codex identity checks and context parsing use the same file snapshot.
- Stream signed ledger records and retain the newest 16 optional edit, question, plan, or Stop cache payloads in hook context. Older cache misses require fresh review. Complete decisions, user history, and receipt checks remain intact.
- Add regressions for memory retention, append snapshots, identity conflicts, signature validation, and fresh review after cache expiry. Update both plugin manifests and operation guidance.

## Verification

All 345 tests passed under system Python and Homebrew Python. The suite used a canonical temporary directory and permission for its nested macOS sandbox checks. Diff whitespace and installed module equality passed. Native Codex consultation returned a new ADVISORY receipt after activation. Detailed measurements are in [the probe report](../probes.md#hook-memory-correction-2026-10-12).

## Residual risk

Memory still depends on retained authority, tool text, and the largest individual record. The additional Codex pass increased parsing and fingerprinting time from 2.01 to 2.92 seconds in the measured sample. Process snapshots do not establish a long-term memory bound. Native Claude activation was not verified.
