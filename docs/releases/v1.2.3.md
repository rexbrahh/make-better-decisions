# v1.2.3

## Outcome

The Claude installer now covers every Claude config dir, not only `~/.claude`. It leaves native launchers such as Adrafinil unwrapped, as the Codex installer already does. Claude can save auto memory notes again.

## Change classes

- Find Claude config dirs at install time: `~/.claude` with `~/.claude.json`, each `~/.claude-*` dir that holds a `.claude.json`, and `$CLAUDE_CONFIG_DIR` when set. A launcher can set `CLAUDE_CONFIG_DIR` for each session, so the installer does not rely on its own shell.
- Read MCP servers from the `.claude.json` of each config dir. Each server records its source file path.
- Write-protect each config dir's `settings.json`, `settings.local.json`, `.claude.json`, `plugins/installed_plugins.json`, and `projects/`. Symlinked entries resolve to one protected path.
- Make `--claude-json` repeatable. Explicit paths replace discovery, as `--claude-plugin-manifest` does.
- Remove native launchers from the Claude command matchers. The installer still records them. Rename `NATIVE_CODEX_SERVERS` to `NATIVE_SERVERS`.
- Deny Claude file-tool writes only to `projects/**/*.jsonl`, the transcripts that the hook reads. Remove the whole-root `projects` and `projects/**` tool rules that earlier installs wrote. Auto memory notes under `projects/<project>/memory/` are writable again. The Bash sandbox and MCP isolation still deny writes to all of `projects/`.

## Evidence

- Claude sessions on this machine start through a launcher that exports `CLAUDE_CONFIG_DIR=~/.claude-primary`. That session writes its transcript under `~/.claude-primary/projects/` and updates `~/.claude-primary/.claude.json`. The v1.2.2 installer read and protected only `~/.claude.json`.
- The v1.0.3 and v1.2.2 Claude plans both put the Adrafinil command in `claude_matchers`, so the shell prefix isolated it. The Codex plan already left Adrafinil under host ownership.
- No auto memory file in any project changed after 2026-10-13 21:44 (558 files). Two memory writes in this release session failed with "Permission to edit ... has been denied". `~/.claude/settings.json` held `Write(//Users/rexliu/.claude/projects/**)`. Claude Code applies a deny rule when the requested path or its symlink target matches. A `!` negation cannot reopen a `//`-anchored rule, so the installer must narrow the rule itself.
- The hook reads only `.jsonl` files under `projects/`: the host transcript path, the host agent transcript path, or `<session>/subagents/agent-<id>.jsonl`.
- Decision receipts: `review_a03b128076fb477fa713e6d526ad22a6` (discovery), `review_ceac840a43cc42e595c0da544822246f` (protected files), and `review_438433ec15df4ef48327c035fa543174` (reader shape). The owner selected replacement semantics for `--claude-json` and the `projects/**/*.jsonl` transcript rule. Jev preferred a narrower two-pattern rule, but that rule failed the invariant that file tools cannot write any transcript the hook reads.

## Verification

The five new or changed regressions fail on v1.2.2 code and pass on v1.2.3. All 375 tests pass under macOS system Python 3.9.6 and Homebrew Python, outside the Claude Code Seatbelt sandbox. A dry run without `CLAUDE_CONFIG_DIR` protects `~/.claude.json`, `~/.claude-primary/.claude.json`, and `~/.claude-secondary/.claude.json`, records Adrafinil, and wraps no native launcher. Against the current `~/.claude/settings.json`, it replaces the eight whole-root `projects` tool rules with four `projects/**/*.jsonl` rules and keeps `projects` in the sandbox `denyWrite` list.

## Residual risk

- The installer writes the shell prefix only to the `--claude-settings` file, which defaults to `~/.claude/settings.json`. A config dir with its own non-symlinked `settings.json` does not get the prefix.
- Plugin manifest discovery reads only `~/.claude/plugins/installed_plugins.json`. A config dir with its own plugin registry is not read.
- A config dir created after installation is not covered until the installer runs again.
- Claude file tools can now write non-transcript files under `projects/`, such as `tool-results/`. The hook does not read them.
- Reinstallation removes the exact whole-root `projects` tool rules. It also removes such a rule if the owner wrote it by hand.
- The native exemption matches by server name. A third-party server that uses a native name runs unwrapped on both hosts.
- On Linux, bubblewrap isolation requires each protected path to exist. More config dirs add more required paths.
