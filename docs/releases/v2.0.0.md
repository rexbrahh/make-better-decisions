# v2.0.0

## Outcome

One Go binary, `agent-decisions`, replaces the Python engine. The binary runs the hook, the installer, the stdio isolation launcher and the Codex shell prefix. Python is not necessary at run time.

The hook output, the ledger rows and their HMAC seals are byte-identical to version 1.2.8. Existing ledgers continue to verify.

## Change classes

- `bin/agent-decisions-install` is a POSIX shell script. It downloads the release binary for this platform, compares its SHA-256 with `bin/agent-decisions.sha256`, and then runs `agent-decisions install`. A hash mismatch stops the installer before it changes anything.
- The repository does not hold the binary. Only the installer gets it. Each runtime bundle holds its own copy at `bin/agent-decisions`, with the pin file.
- The hook launchers run `bin/agent-decisions hook` from the installed runtime. If the active runtime is from a release before 2.0.0, the launchers run its Python hook. If no runtime is installed, the launchers deny reviewed tool calls and tell you to run the installer.
- `bin/agent-decisions-isolate` and `bin/agent-decisions-shell-prefix` run the binary beside them. In a plugin root, which has no binary, they run the binary of the active runtime.
- Each runtime bundle also holds `hooks/hook.py`, a 4-line Python file that runs the binary. A host session that started before the upgrade still runs the launcher of version 1.2.8, which runs this file. Without it, those sessions would deny every reviewed tool call until a restart.
- `scripts/build-release` builds the darwin-arm64 and linux-amd64 binaries with Go 1.27.2 and writes their pins. The build is reproducible.
- The Python engine, its unit tests and the live QA scripts are removed. The signed tag `python-final` holds them.

## Evidence

- Measured on 2026-10-14 and 2026-10-15 on darwin-arm64.
- Real replay: 6,206 hook calls from 48 real Claude and Codex transcripts went through both engines. The two engines gave 0 differences in stdout, error text, Jev requests and ledger lines. The Go engine took 1 min 40 s. The Python engine took 2 min 5 s, including interpreter start for each transcript.
- Synthetic transcript of 4,000 turns: a gated Claude call took 0.6 s in Go and 1.25 s in Python. A gated Codex call took 1.55 s in Go and 9.3 s in Python.
- A `session_start` call took 7.3 ms in Go and 55 ms in Python. A Codex shell prefix took 5.2 ms in Go and 31.6 ms in Python.
- The owner chose "Installer-only download" and "Release asset + SHA-256 pin" for the binary.

## Verification

- `go test ./...` passes. The oracle tests also pass against CPython 3.15 and the `python-final` checkout.
- New tests run each hooks.json launcher through `/bin/sh` for 4 cases: installed binary, Python runtime from an earlier release, failed engine, and missing engine. A further test runs the launcher of version 1.2.8 against a Go runtime.
- The installer was run in a temporary home. A pinned binary installed. A binary with a different hash was refused.
- Two builds with empty build caches gave the same SHA-256 values.

## Upgrade

1. Update the plugin in Claude Code and Codex.
2. Run `bin/agent-decisions-install --apply` from the plugin root.
3. In Codex, trust the changed hooks again.
4. Restart running agents when it is convenient. After step 2, running agents use the Go engine through `hooks/hook.py`. New agents use it directly.

## Residual risk

- The binary is not verified on Linux. The linux-amd64 build compiles, but no test ran on Linux.
- Linux bubblewrap isolation is not runtime verified, as in earlier releases.
- Between step 1 and step 2 of the upgrade, the earlier Python runtime continues to run.
