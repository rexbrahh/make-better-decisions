# v2.2.17 — Snap default and shell classification

SubQ Snap is the default reviewer for new installations.
The model chooser presents Snap first and retains Jev as the second choice.
Jev's API client, response validation and receipt identity remain available.
Existing installations retain their provider until the owner changes it.
Rex explicitly selected Snap for both native hosts on this Mac.

To change the provider, run:

```sh
~/.local/share/agent-decisions/current/bin/agent-decisions provider
```

Select a model and host, inspect the plan, then type `apply`.
Blank input cancels. The installer also accepts `--review-provider subq` or `--review-provider jev`.
Provider selection stays in signed host policy. It cannot come from a review request or an environment variable.
Snap reads the existing environment key or managed SOPS secret.
This release stores no credential in installation policy.

The classifier now distinguishes quoted data from executable shell input with bounded syntax assistance.
It retains commands after a data heredoc, recognizes active redirects and handles static ANSI quotes.
Shell-stdin bodies receive a separate parse. Original standalone request bytes remain unchanged.
The shared parse budget is eight times the original input length.
Budget exhaustion retains the original source for conservative detection.

The parser is pinned to upstream commit `f6d205ab76b3e5e89073130c2229a43be04e1e2a`.
Its BSD notice ships in the plugin, immutable runtime and release assets.
This is a development commit with experimental Zsh support.
The classifier retains the existing conservative treatment of shell-named consumers, including `sh -c`.

Required review, private-state protection, provider isolation and existing session exceptions remain active.
Old Jev receipts do not become Snap approvals. The plugin does not fall back to Jev after a Snap failure.
Snap remains a public preview model.
