# v1.1.0

Material engineering choices retain independent Jev review. Verified parents can assign eligible scoped decisions to workers. Routine implementation and checks continue through the existing classifier.

## Changes

- Added receipt ids, captured native ancestry, completed parent dispatch checks, and repository/path scopes.
- Added option/invariant checks, uncertain worker routing, stable wording repairs, and concrete denial diagnostics.
- Made required review the default. Runtime failures block unchecked operations. Signed installation policy can select visible availability mode.
- Added source/baseline labels, command exit metadata, fresh source/contract coverage, and durable signed architecture history.
- Added timings and usage records. Sampled context construction is roughly one-third faster with identical retained evidence.

## Upgrade

Install version 1.1.0 through the marketplace. Apply the boundary helper from that installed version. Use `--review-mode required` for the default enforcement policy.

```sh
codex plugin add agent-decisions@make-better-decisions
python3 /path/to/installed/agent-decisions/bin/agent-decisions-install --host codex --review-mode required --install-root /path/to/installed/agent-decisions --apply
```

Trust the five updated hooks through Codex registration. Restart existing tool sessions to load changed stdio launchers. Availability permits runtime failures with warnings and weakens enforcement. Startup failures still block reviewed operations because the launcher cannot verify signed policy.

`AGENT_DECISIONS_OFF` no longer disables review. An unverified result grants no reusable approach receipt. Changed scoped source or contract hashes require fresh coverage for later material choices.

## Verification

The implementation passed 315 local tests, including macOS isolation. Real-Jev core and ergonomics suites passed 65 cases. A native-shaped scoped fixture passed five checks with three API calls. Independent review found one stale-source defect, fixed through failing regressions.

These checks do not establish general model accuracy. Live GUI activation, Linux bubblewrap, and trusted HTTP services require separate acceptance evidence. Nested Claude inheritance remains unsupported.
