# Add optional SubQ Snap review

Owners can select `subq-snap-preview` through the protected installer with `--review-provider subq`.
TypeSafe Jev remains the default. An omitted flag preserves the existing host selection.
The [installation guide](../../README.md#optional-subq-snap-provider) covers keys, selection and recovery.

Snap retains up to 800,000 serialized evidence characters and 160,000 characters per excerpt.
It divides questions into batches of at most 16 over the same scrubbed state.
At most four requests run within one ten-second review deadline.
Every answer and the response model must pass validation before the gate receives any results.
Request and response limits, redirect rejection, cancellation and sanitized errors bound transport failures.

Provider, model, context profile and review contract isolate receipts, caches and parent inheritance.
The selected provider requires its own key. Both available provider keys are redacted before export or storage.
Invalid signed selections block reviewed tools, including in availability mode.
An explicit valid installer selection can repair an invalid prior selection.
Review thresholds, healthy denials, source provenance, input limits and private-state protection remain active.

Initial live checks cover six labeled gate cases and a 33-question long-input review across three batches.
Native Codex and Claude checks each produced a Snap receipt across two batches and completed an exact edit.
These checks do not establish calibration or qualify the full advertised context window.
Snap remains optional while stability qualification continues.
See the [QA record](../validation/v2.2.0-qa-2026-10-16.md) for evidence and remaining limits.

Unit suite, frozen Jev oracle, live Jev gates, vet and diff checks pass.
The oracle permits only the additive provider-option help text. Both release assets match their SHA-256 pins.
