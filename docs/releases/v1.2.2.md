# v1.2.2

## Outcome

Each refusal now names the repair for its reason. An unintercepted consultation now gives a recovery path instead of an unanswerable registration check.

## Change classes

- Add a `repair:` line for `missing_option`, `missing_existing_helper`, `pick_conflicts_with_instruction`, and `none_fit` refusals. The helper repair shows the `helper_present` and `helper_in_options` scores.
- Print the text of each failed invariant on a refusal. Previously only a gather result showed it.
- Rewrite the `bin/ts-decide` stub message. A standalone retry separates a malformed call from a session that did not load the hook. In a session without a hook, the agent decides with stated evidence and asks the user to restart or resume the session.
- Add the `did not intercept` row to the skill and spec verdict tables.

## Evidence

- Codex sessions recorded 57 refusals: 35 `argued`, 15 `missing_option`, 5 `none_fit`, 1 `missing_existing_helper`, and 1 invariant. Only `argued` printed a repair. The owner thread stopped after two refusals at 02:16Z and 02:23Z on 2026-10-14. The second refusal was `missing_existing_helper`, and the request already named the helper.
- Field Store CLI PID 97236 started at 8:08 p.m. Toronto time. Hook restoration completed at 8:35 p.m. Its registrations were enabled and trusted, and its call still exited 3. The old stub sent the agent to check registration and trust, which were already correct.

## Verification

The new regressions failed before the change. All 371 tests pass under macOS system Python 3.9.6 and Homebrew Python. Seven native-sandbox tests need a run outside the Claude Code Seatbelt sandbox, because nested `sandbox-exec` cannot apply inside it.

## Residual risk

Jev identifies a refusal reason but not the missing alternative or helper by name. The agent finds that item in the evidence. The stub cannot tell a malformed call from a session without a hook. The standalone retry makes that distinction. An unintercepted call still exits 3 and grants no decision authority.
