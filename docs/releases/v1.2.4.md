# v1.2.4

## Outcome

On Claude, a native launcher runs unwrapped only when the owner's own `settings.json` or `.claude.json` defines it. A plugin manifest server that uses a native name stays isolated.

## Change classes

- Exempt a server in `NATIVE_SERVERS` from the Claude command matchers only when its source is the owner's settings or a discovered `.claude.json`. Plugin manifest servers always get a matcher.
- Name the settings source `CLAUDE_SETTINGS_SOURCE` so the reader and the exemption use one value.

## Evidence

- An automated review of the v1.2.3 commit found that the name-only exemption lets a plugin server named `computer-use` or `messages` run unwrapped. The regression test reproduces this on v1.2.3: the plan wrapped only `/bin/echo` and left both plugin servers unwrapped.
- The review stated that the Codex path verifies the launcher. That is not correct. `_is_codex_wrapper_transport` only recognizes an earlier agent-decisions wrapper so that the installer can restore it.
- A second review suggested that a case variant such as `PROJECTS/` or `.JSONL` could get past the v1.2.3 transcript rule, because this volume is case-insensitive. With the v1.2.3 rule active, three Write calls to the memory folder were all denied: `case-probe.jsonl`, `PROJECTS/.../case-probe-dir.jsonl`, and `case-probe-ext.JSONL`. A `.md` note through `PROJECTS/` was written. Claude Code matched these rules without regard to case, so no change was made.

## Verification

The native-exemption regression fails on v1.2.3 and passes on v1.2.4. All 375 tests pass under macOS system Python 3.9.6 and Homebrew Python, outside the Claude Code Seatbelt sandbox. A dry run reads Adrafinil from `~/.claude.json` and leaves it unwrapped.

## Residual risk

- The Claude exemption trusts the server name in owner config. The installer does not verify the launcher binary.
- On Codex, the native exemption is still by name only.
- The case-insensitive match was observed on one macOS volume. Other volumes and hosts were not tested.
