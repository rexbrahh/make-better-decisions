# Redact complete inline secret arguments

## Outcome

A secret value in one `--flag=value` argv element is fully redacted, including spaces, tabs and newlines.

## Change classes

The list sanitizer reuses the existing secret-flag helper before generic string sanitization.
It treats inline secret values as opaque, as it already does for separate secret-value arguments.
Nonsecret arguments, scalar string sanitization and separate flag/value handling retain their paths.

## Evidence

All nine supported flag spellings leak the suffix after the first word before the fix.
The new regression passes afterward, with nonsecret and separate-value controls.
The unchanged Python oracle also passes.
Its old list fixture masked the leak by placing an inline token immediately after a standalone secret flag.

## Verification

Unit suite, complete Python oracle, live Jev gates, vet and diff checks pass.
Both release assets match their SHA-256 pins.

## Upgrade

Update both native plugins and run their protected installers. Trust the changed Codex hooks.

## Residual risk

Unknown flag names retain the existing generic sanitization behavior.
GUI operation and live worker inheritance remain unverified.
