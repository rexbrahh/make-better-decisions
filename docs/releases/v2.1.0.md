# Use the selected Claude configuration

## Outcome

When `CLAUDE_CONFIG_DIR` selects a configuration directory, the installer uses its settings and plugin registry.
The directory can be outside the user's home.
Explicit settings selection and the `~/.claude` fallback remain available.

## Change classes

A private helper selects the default configuration root for both callers.
All-root protection and native server ownership retain their behavior.
Manifest inventory also sends bare server maps through the existing normalization and validation helpers.
Wrapped and legacy manifest forms remain supported.

This completes ten maintenance rounds from v2.0.2 through v2.1.0.
See the [campaign](../validation/v2.1.0-campaign-2026-10-15.md).

## Evidence

The selected-root regression failed settings and registry assertions before the fix.
It now covers unset, empty, absolute and tilde-expanded selections, plus explicit settings overrides.
Two installed bare stdio manifests exposed a further omission.
Their regression now passes, including macro expansion, source identity and rejection of invalid argv.

The frozen Python CLI comparison uses explicit paths for its selected-directory case.
Direct Go regressions verify the corrected defaults that the Python baseline predates.

## Upgrade

Update both native plugins and run their protected installers.
Set `CLAUDE_CONFIG_DIR` before the Claude installer when you use a separate configuration directory.
Trust the changed Codex hooks and start a fresh host session.
